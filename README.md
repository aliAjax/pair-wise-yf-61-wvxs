# 远程设备固件分批发布控制台

源提示词摘要：发布负责人选择设备范围、固件版本、分批比例和回滚版本，运维设定兼容条件与失败阈值，值班人员监视下载、安装、重启和异常事件；关键发布支持审批、暂停、继续和紧急回滚，过期状态不可误用。

本版在控制台只填"目标版本/回滚版本"的基础上，补齐**按固件仓库版本谱系为每种机型规划升级路线**的能力。

## 技术栈

Angular、TypeScript、Angular Material、NgRx、Angular Router、RxJS、Angular CDK、Transloco。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62026`

## 路线规划规则

固件仓库是一张按机型划分的版本 DAG（`src/app/state/firmware.seed.ts`），每个版本声明"允许从哪些版本直接刷入"：

- **过渡版本**：老机型跨大版本不能直升（如 X100：`2.4.0 → 2.6.0(过渡) → 2.8.2 → 2.9.1(过渡) → 3.0.0 → 3.1.2`），规划器在机型子图里 BFS 找最短路。
- **引导程序**：换过主板的网关机型，路线第一步自动补刷 `boot-*` 引导节点。
- **缺环节退回草稿**：目标版本不可达时，沿前置关系反向排查并**指名缺失版本及引用方**（如 `3.1.9（被 3.2.0 引用但固件仓库缺失）`），整个批次留在草稿，审批按钮禁用。
- **可绕行不误报**：某版本的前置缺失但目标另有可达链路（如诊疗终端 `3.4.0` 缺 `3.3.5`，但 `3.4.2` 可从 `3.3.0` 直达）时，不报缺口。

## 失败重试（替代路线）

某机型刷写失败后：

1. 路线状态置 `failed`，批次自动暂停，记录失败边（如 `2.8.1->2.9.0`）并停在 `reachedVersion`；
2. 值班员点"从已到版本重试"，规划器从 `reachedVersion` 出发、**避开所有失败边**重新 BFS：优先回滚稳定版，其次原目标，最后兜底最近可达稳定版；
3. 示例：E300 的 `2.9.0` 过渡通道失败后改走并行通道 `2.8.1 → 2.9.1 → 3.0.0 → 3.1.2`。

## 依赖变更与并发

- 每次修改某版本的前置依赖，全局 `graphRevision` 与节点 `prereqRevision` 递增：
  - **未下发**的路线（草稿/已审批/在刷批次的剩余步骤）立即按新谱系失效重算；
  - **已刷好**的设备保留结果（`done`/`rescued` 路线冻结），重算只保留已完成步骤前缀，替换未下发的尾巴；
  - 依赖被改断的已审批/发布中批次退回草稿并指名缺口。
- **乐观锁**：提交依赖修改需携带打开编辑器时的基线修订号；两名值班员同时改同一节点时，后到者（基线过期）会看到冲突横幅，指名先提交者与双方修订号，修改被拒绝，刷新基线后才能再改。页面提供"模拟对班先提交"按钮用于演示。

## 持久化

状态（含固件谱系、修订号、批次路线、审计）写入 localStorage 键 `firmware-release-v2`，跨刷新保留；清除该键可恢复种子演示数据。

## 逻辑自检（无需浏览器）

```bash
npx tsx scripts/verify-planner.ts   # 20 项：寻路/引导/缺口/替代路线/重算
npx tsx scripts/verify-reducer.ts   # 34 项：批次生命周期/失败救援/依赖重算/并发冲突
```

## 可用流程

- 创建发布批次：只填目标版本与回滚版本，系统按分组内每种机型的当前版本分别算路。
- 批次从草稿、已审批、发布中、暂停到完成或回滚；缺环节机型阻止审批。
- 机型级失败重试与重新规划；审批、暂停、继续、回滚、依赖编辑均保留审计记录。
